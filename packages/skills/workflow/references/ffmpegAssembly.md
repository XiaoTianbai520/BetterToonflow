# FFmpeg 自动合成单集成片

用户要求完整单集且视频与配音已生成、核验并采用后执行。这里只处理媒体合成，不改写主 `SKILL.md` PART A 的剧情与提示词；需要补生成或重抽时，先回到主技能的 `askUser` 算力硬门控。

滤镜语义参照 [FFmpeg 官方文档](https://ffmpeg.org/ffmpeg-filters.html)，具体可用参数以本机版本和工具实时 schema 为准。

## 1. 固定本集顺序与真实输入

- 在当前工作区读取目标画布的分镜节点、连线及采用记录，分页补齐。生成节点若切换过 `mediaHistory`，固定本次采用版本的真实路径，不追随之后变化的当前输出。
- 从画布分镜依赖得到拓扑约束，结合已确认剧本/全局镜头号形成唯一播放序列。角色/场景参考图入边只是素材依赖，不是镜头先后；同层独立节点不能仅靠拓扑排序确定播放顺序，须按已确认镜头号消解。循环、冲突或缺少可确定的先后关系时只澄清受影响项，不按坐标、创建时间或文件名排序。
- 把镜头清单并入已有制作台账：镜头号、节点/版本、视频路径、采用区间 `[in,out)`、角色/台词、配音文件、镜内起点、原声保留/压低/替换方案。没有裁切要求时采用完整视频。不得静默跳过缺镜、未完成生成或未采用素材。
- 输入、临时中间片与输出都位于当前工作区；包括滤镜、原生选项及清单里间接引用的路径。拒绝越界路径与远程 URL，不能把工具对显式入口的检查当成所有原始参数的沙箱。输出子目录须已存在或经现有工作区能力创建。

## 2. 逐镜逐轨 ffprobe 与依赖检查

通过内置 `ffprobe` 读取每个视频和角色配音，不根据生成参数猜实际时长：

```json
{ "path": "assets/镜头01.mp4" }
```

记录 `format.duration` 与 `streams` 中的视频宽高、帧率、编码、起始时间，以及音轨索引、时长、采样率、声道。对容器时长与视频轨明显不一致、时长缺失/非正、视频轨缺失或无法解码的素材先定位问题；必要时使用工具实际支持的进一步探测，不把异常时长当零处理。音频只有音轨是正常情况，视频没有音轨则登记“需补静音”。

用 `ffmpeg` 能力查询确认目标编码器与所需滤镜真实可用，例如：

```json
{ "steps": [], "operation": { "method": "availableEncoders", "args": [] } }
```

滤镜查询使用 `availableFilters`。所有 `ffmpeg` 请求采用工具真实的 `steps` / `operation` schema；`steps` 按序调用 fluent 方法，不是命令行字符串，不传 JavaScript、shell 或回调。宿主负责转为网关 `calls`，Agent 不手工请求网关。依赖缺失（如 `424` / `FFMPEG_REQUIRED`）时停止合成，说明需先使 FFmpeg/FFprobe 就绪；不循环重试、擅自安装或假报成功。

## 3. 按镜头对齐角色配音并统一规格

沿用本集画幅、尺寸和帧率；无明确交付值时从已采用视频选择相容规格并记录。默认兼容目标为 MP4、H.264（如本机存在 `libx264`）、`yuv420p`、AAC、48 kHz 双声道。保持宽高比并以 `scale` + `pad` 补边，统一偶数尺寸、SAR、帧率和时间基；不能默认拉伸画面。

每镜以实际采用区间确定时长 `T = out - in`：

1. 视频使用 `trim`（有裁切时）、`setpts=PTS-STARTPTS`，再统一尺寸、帧率与像素格式。源轨带旋转元数据时按实际显示方向核对输出，避免重复旋转。
2. 原声音轨按同一采用区间裁取并 `asetpts=PTS-STARTPTS`，`aresample` / `aformat` 统一采样率与声道；按已确认方案保留、压低或替换。原生对白已覆盖该角色台词时不重复叠加 TTS；混合音轨无法分离对白与环境声时先明确取舍，不声称能无损移除原声对白。
3. 每条角色配音先重置时间戳、统一格式，再按镜内起点 `s` 执行 `adelay`；双声道可用毫秒参数如 `adelay=500|500`。同一角色保持已采用声线；多角色对白各有独立起点，不能把所有配音从零同时播放。起点来自已确认台词/时间轴，缺失时按剧本节拍给出对齐提案，不能凭音频文件排列猜。
4. 先核对 `s >= 0` 且 `s + 实测配音时长 <= T`。若配音超出镜头、重叠违背原对白或镜头裁切会丢台词，停止该镜并处理采用区间/时长方案；不默认加速配音、删字或截断。需要重新生成音频时重新走算力授权。
5. 保留的原声、配音和已采用音乐用 `volume` / `amix` 按方案混合，并控制峰值（如 `alimiter`，使用时补偿其延迟）。用 `apad` 补齐不足部分，再 `atrim` 到 `T`，最后重置时间戳。无任何声音的镜头用 `anullsrc` 生成同规格静音并裁到 `T`，保证每个中间片都有一条等长音轨。

镜内起点以裁切后的片段为零点。若声音标注采用源视频时间码，应先减去 `in`；若采用整集时间码，应先减去该镜在整集的累计起点。镜头 `i` 的全局起点为此前各镜实际采用时长之和，跨镜配音按该全局时间轴处理，不在每个镜头重新播放整条配音。

以下为**单镜调用示例**：已探测采用视频完整长 4 秒，配音长 3.2 秒、从镜内 0.5 秒开始，已选择以配音替换原声；本集规格为 1280×720 / 25 fps，所用目录、编码器与滤镜均已就绪。实际调用须替换真实路径、规格、时长与滤镜，示例不授权覆盖文件或实际生成。

```json
{
  "steps": [
    { "method": "input", "args": ["assets/镜头01.mp4"] },
    { "method": "input", "args": ["assets/角色甲_镜头01.wav"] },
    { "method": "complexFilter", "args": ["[0:v:0]trim=start=0:end=4,setpts=PTS-STARTPTS,scale=1280:720:force_original_aspect_ratio=decrease,pad=1280:720:(ow-iw)/2:(oh-ih)/2,setsar=1,fps=25,format=yuv420p,settb=AVTB[v];[1:a:0]asetpts=PTS-STARTPTS,aresample=48000,aformat=sample_fmts=fltp:sample_rates=48000:channel_layouts=stereo,adelay=500|500,apad,atrim=duration=4,asetpts=PTS-STARTPTS[a]"] },
    { "method": "outputOptions", "args": ["-map", "[v]", "-map", "[a]", "-c:v", "libx264", "-pix_fmt", "yuv420p", "-c:a", "aac", "-ar", "48000", "-ac", "2", "-movflags", "+faststart", "-n"] }
  ],
  "operation": { "method": "save", "args": ["assets/镜头01_合成v1.mp4"] }
}
```

保留原声并叠加两条角色配音时，先分别处理为 `[base]`、`[voiceA]`、`[voiceB]`，再以类似 `[base][voiceA][voiceB]amix=inputs=3:duration=longest:normalize=0,alimiter=limit=0.95:latency=1,apad,atrim=duration=4,asetpts=PTS-STARTPTS[a]` 的链混音；各输入音量先按方案降低，防止多轨叠加削波。此处 4 秒仍是示例，必须用该镜实际 `T`。只有单条配音时无需引入 `amix`。

每镜完成后再次探测中间片，核对视频与音轨都覆盖 `T`，记录按帧对齐产生的实际时长。后续用此实测值累计时间轴；不能把源视频请求时长当作中间片时长。

## 4. 按序 concat 拼接并转码输出

默认使用已统一规格且含音轨的中间片，通过 `concat` 滤镜交错输入视频和音频；各段时间戳必须从零开始。下面演示两镜，实际按锁定清单扩展到 `N` 镜，输入标签依序为 `[0:v][0:a]…[N-1:v][N-1:a]`，`concat=n=N:v=1:a=1`。若素材较多超出工具或进程参数上限，按连续顺序分批合成中间片后再合并，保持原镜头顺序。

```json
{
  "steps": [
    { "method": "input", "args": ["assets/镜头01_合成v1.mp4"] },
    { "method": "input", "args": ["assets/镜头02_合成v1.mp4"] },
    { "method": "complexFilter", "args": ["[0:v:0]settb=AVTB,setpts=PTS-STARTPTS[v0];[0:a:0]asetpts=PTS-STARTPTS[a0];[1:v:0]settb=AVTB,setpts=PTS-STARTPTS[v1];[1:a:0]asetpts=PTS-STARTPTS[a1];[v0][a0][v1][a1]concat=n=2:v=1:a=1[v][a]"] },
    { "method": "outputOptions", "args": ["-map", "[v]", "-map", "[a]", "-c:v", "libx264", "-pix_fmt", "yuv420p", "-c:a", "aac", "-ar", "48000", "-ac", "2", "-movflags", "+faststart", "-n"] }
  ],
  "operation": { "method": "save", "args": ["成片_第1集.mp4"] }
}
```

输出默认工作区根目录；用户指定子目录时输出到该目录。同名已存在使用 `成片_第1集_v2.mp4` 等新名，不添加覆盖选项。显式 `-n` 避免并发同名覆盖。先前成片与所有采用源素材均保留，不把输出路径指向输入文件。不用 `-shortest` 掩盖音轨不足或丢失后半集。

## 5. 等待终态、核验与交付

- 顺序等待每次 `ffmpeg` 完成，前一镜失败不得继续最终拼接；有进度或启动回执不代表成功。错误/取消时记录失败阶段、输入和实际返回，不自动重抽素材或删除输入；部分输出标记未完成，修复后使用新输出名。重跑前重新核对采用文件与顺序。
- 对最终实际文件调用 `ffprobe`，核对有可解码的视频和音轨、尺寸/帧率/编码符合本集规格、时长接近各中间片实测采用时长之和。按帧间隔和音频编码延迟解释小差异；明显短片、黑屏段或音轨缺失不能交付为已完成。
- 按实际能力检查镜头切点、首尾、角色台词起点/结束与峰值，区分技术探测与完整视听审片。无法听看全片时明确未核验项，由用户在文档工作台媒体播放器预览；`ffprobe` 成功不证明剧情、口型或声音内容正确。
- 交付真实工作区相对路径（如 `成片_第1集.mp4`）、实测时长和规格；把顺序清单、声音方案、输出版本及已核验/待预览项写回既有制作状态。八镜黄金场景必须实际包含八段采用视频与对应配音，不能以素材链接列表或未结束任务替代单集成片。
